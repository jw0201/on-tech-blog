코딩 에이전트는 파일을 읽고, 수정하고, 테스트를 실행하고, 때로는 네트워크 요청까지 수행합니다. 편리하지만 권한 경계가 흐리면 위험합니다. "에이전트를 믿을 수 있는가"보다 좋은 질문은 "에이전트가 실수해도 피해가 제한되는가"입니다.

권한 모델은 복잡한 보안 제품처럼 시작할 필요가 없습니다. 파일, 명령, 네트워크 세 가지 축으로 나누면 대부분의 팀에서 실용적인 기준을 만들 수 있습니다.

## 파일 권한은 작업 단위로 좁힌다

에이전트가 전체 저장소를 읽는 것은 흔하지만, 전체 저장소를 쓰는 것은 별개의 문제입니다. 특히 배포 설정, 인증 설정, 결제 로직, 마이그레이션 파일은 별도 보호가 필요합니다.

권한을 다음처럼 나눌 수 있습니다.

- 읽기 가능: 저장소 전체, 문서, 테스트
- 기본 쓰기 가능: 기능 코드, 테스트, 로컬 문서
- 승인 후 쓰기: CI 설정, 인프라 코드, 마이그레이션
- 쓰기 금지: 비밀 파일, 개인 설정, 프로덕션 키

중요한 것은 경로 규칙을 문서로만 두지 않는 것입니다. 에이전트 실행 환경이 실제로 해당 경로 변경을 막거나, 최소한 변경 시 명시적 승인을 요구해야 합니다.

## 명령은 allowlist로 시작한다

`npm test`, `go test`, `pytest`는 대체로 안전하지만 `rm`, `curl | sh`, `terraform apply`는 성격이 다릅니다. 명령 권한은 셸 전체를 허용하는 방식보다 allowlist가 안전합니다.

처음에는 다음처럼 단순하게 시작할 수 있습니다.

```text
허용:
- npm test
- npm run lint
- npm run build
- git diff
- rg

승인 필요:
- npm install
- docker compose up
- database migration
- deploy command

금지:
- production credential access
- destructive cleanup
- remote shell execution
```

패키지 설치는 특히 조심해야 합니다. 의존성 추가는 코드 변경보다 공급망 리스크가 큽니다. 에이전트가 새 패키지를 제안할 수는 있지만, 설치와 커밋은 사람의 검토를 거치는 편이 좋습니다.

## 네트워크는 목적별로 제한한다

AI 에이전트가 문서를 검색하거나 패키지 정보를 확인하려면 네트워크가 필요합니다. 하지만 네트워크 허용은 데이터 유출 가능성도 함께 엽니다.

네트워크 정책은 목적별로 나누는 것이 좋습니다.

- 공식 문서와 패키지 레지스트리 조회
- 회사 내부 API 조회
- 외부 웹 검색
- 코드나 로그를 외부 서비스로 전송

마지막 항목은 기본 금지에 가깝게 다뤄야 합니다. 로그, 고객 데이터, 소스 코드 일부가 검색 쿼리나 요청 본문에 섞일 수 있기 때문입니다.

## 감사 로그는 사람의 언어로 남긴다

권한 모델은 나중에 확인할 수 있어야 의미가 있습니다. 에이전트가 어떤 파일을 읽고 썼는지, 어떤 명령을 실행했는지, 어떤 네트워크 요청을 했는지 남겨야 합니다.

다만 감사 로그가 너무 낮은 수준이면 아무도 읽지 않습니다. 운영에 필요한 최소 정보는 다음입니다.

- 작업 요청과 작업자
- 수정된 파일 목록
- 실행한 명령과 종료 코드
- 승인 요청과 승인자
- 실패한 권한 요청

특히 실패한 권한 요청은 중요합니다. 에이전트가 반복적으로 금지된 경로를 수정하려 한다면 프롬프트, 작업 분해, 권한 정책 중 하나가 잘못된 것입니다.

## 권한은 작업 유형에 따라 달라져야 한다

문서 수정, 테스트 추가, 버그 수정, 배포 작업은 필요한 권한이 다릅니다. 모든 작업에 같은 권한을 주면 작은 작업도 큰 위험을 갖게 됩니다.

예를 들어 다음과 같은 프로필을 만들 수 있습니다.

- `read-only-review`: 읽기와 테스트 실행만 허용
- `safe-edit`: 애플리케이션 코드와 테스트 수정 허용
- `infra-change`: 인프라 코드 수정은 가능하지만 적용은 승인 필요
- `release`: 태그, 배포, 릴리스 노트 작업은 별도 승인 필요

프로필이 있으면 에이전트 사용 경험도 좋아집니다. 사용자는 매번 권한을 설명하지 않고 작업 성격만 고르면 됩니다.

## 체크리스트

- 파일 쓰기 권한을 경로와 작업 유형별로 나눴다.
- 명령 실행은 allowlist에서 시작한다.
- 네트워크 접근은 목적별로 제한한다.
- 실행 기록과 승인 기록이 감사 가능하게 남는다.
- 작업 유형별 권한 프로필을 제공한다.

코딩 에이전트의 생산성은 권한을 넓게 열 때만 생기지 않습니다. 잘 좁힌 권한은 팀이 더 자주, 더 안심하고 에이전트를 쓰게 만드는 기반입니다.
