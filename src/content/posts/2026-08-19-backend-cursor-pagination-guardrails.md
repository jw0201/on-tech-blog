커서 페이지네이션은 큰 목록을 안정적으로 탐색하기 좋은 방식입니다. 하지만 `nextCursor`만 반환한다고 운영 가능한 API가 되는 것은 아닙니다. 정렬 기준이 흔들리거나 커서가 임의로 조작되거나 데이터가 계속 변하면 사용자는 누락과 중복을 경험합니다.

커서는 단순한 위치값이 아니라 목록 조회 계약입니다. 어떤 조건으로 정렬했는지, 어느 방향으로 이동하는지, 클라이언트가 커서를 어떻게 다뤄야 하는지 명확해야 합니다.

## 정렬은 유일하고 안정적이어야 한다

커서 페이지네이션의 첫 번째 조건은 안정적인 정렬입니다. `created_at desc`만으로는 부족한 경우가 많습니다. 같은 시각에 생성된 행이 여러 개 있으면 페이지 경계에서 순서가 흔들릴 수 있습니다.

보통은 다음처럼 유일한 보조 키를 함께 둡니다.

```sql
order by created_at desc, id desc
```

커서에도 같은 정보를 넣어야 합니다.

```json
{
  "createdAt": "2026-08-19T00:10:00Z",
  "id": "ord_123"
}
```

조회 조건 역시 정렬과 같은 방향으로 작성해야 합니다. 내림차순이라면 다음 페이지 조건은 `created_at < cursor.createdAt` 또는 같은 시각일 때 `id < cursor.id`가 됩니다.

## 커서는 불투명하게 만든다

클라이언트가 커서 내부를 해석하기 시작하면 API 변경이 어려워집니다. 커서는 base64로 인코딩한 JSON일 수 있지만, 문서상으로는 불투명한 문자열이어야 합니다.

운영 환경에서는 커서 서명도 고려해야 합니다. 사용자가 커서를 조작해 다른 테넌트의 데이터를 탐색하거나 지나치게 오래된 조건을 재생할 수 있기 때문입니다.

커서에 포함할 만한 값은 다음과 같습니다.

- 정렬 키
- 필터 해시
- 방향
- 발급 시각
- 버전

필터 해시가 있으면 클라이언트가 이전 필터에서 받은 커서를 새 필터에 실수로 재사용하는 상황을 막을 수 있습니다.

## 변경 중인 목록을 전제로 둔다

목록 데이터는 페이지를 넘기는 동안에도 바뀝니다. 새 항목이 추가되고 기존 항목이 삭제됩니다. 커서 페이지네이션은 offset 방식보다 흔들림이 적지만 완전히 고정된 스냅샷은 아닙니다.

그래서 문서에 기대치를 적어야 합니다.

- 새로 생성된 항목은 이미 지나간 페이지 앞쪽에 나타날 수 있다.
- 삭제된 항목은 다음 페이지에서 보이지 않을 수 있다.
- 같은 항목은 정렬 키가 바뀌면 다시 나타날 수 있다.

정말로 고정된 결과가 필요하다면 커서에 스냅샷 기준 시각을 포함하고 모든 페이지에서 `created_at <= snapshot_at` 조건을 적용하는 방식이 필요합니다.

## 양방향 탐색은 별도 계약이다

`nextCursor`만으로 충분한 목록도 있지만 관리자 화면이나 로그 탐색 도구는 이전 페이지가 필요합니다. 이때 단순히 같은 커서를 반대로 쓰면 정렬과 결과 순서가 꼬이기 쉽습니다.

양방향을 지원한다면 `nextCursor`와 `prevCursor`를 분리하고, 응답 결과의 정렬 순서는 항상 문서화된 방향으로 유지해야 합니다. 내부 쿼리에서 반대 방향으로 조회하더라도 응답 전에 다시 정렬하는 처리가 필요할 수 있습니다.

## 디버깅 가능한 오류를 반환한다

커서 오류는 클라이언트 입장에서 이해하기 어렵습니다. 만료된 커서, 다른 필터의 커서, 잘못 서명된 커서를 모두 `400 Bad Request`로만 돌려주면 원인을 찾기 힘듭니다.

다음처럼 오류 코드를 분리하면 운영이 쉬워집니다.

- `cursor_expired`
- `cursor_filter_mismatch`
- `cursor_invalid_signature`
- `cursor_version_unsupported`

메시지는 사용자에게 노출될 수 있게 짧게 쓰되, 서버 로그에는 커서 버전과 필터 해시를 남기는 편이 좋습니다. 원문 커서 전체를 로그에 남기는 것은 피해야 합니다.

커서 페이지네이션은 성능 최적화 기법이면서 API 계약입니다. 정렬, 보안, 변경 데이터, 오류 모델을 함께 설계하면 목록 조회가 커져도 예측 가능한 경험을 유지할 수 있습니다.
