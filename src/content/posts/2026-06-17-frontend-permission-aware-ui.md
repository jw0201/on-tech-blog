권한 처리는 백엔드의 책임입니다. 하지만 사용자가 실제로 만나는 곳은 프론트엔드입니다. 권한이 없는 버튼이 보였다가 실패하거나, 반대로 필요한 기능이 보이지 않으면 제품은 불안정해 보입니다. 그래서 프론트엔드도 권한을 이해해야 합니다. 단, 프론트엔드 권한 처리는 보안 장치가 아니라 사용자 경험을 정리하는 장치라는 선을 분명히 해야 합니다.

## 권한은 기능 단위로 내려받는다

UI에서 가장 다루기 쉬운 권한 모델은 역할 이름보다 기능 플래그에 가깝습니다. `admin`, `manager`, `member` 같은 역할만 받으면 화면마다 역할 해석 로직이 흩어집니다. 나중에 "매니저 중 일부만 삭제 가능" 같은 요구가 생기면 조건문이 빠르게 복잡해집니다.

대신 서버가 현재 사용자가 할 수 있는 행동을 내려주는 방식이 낫습니다.

```json
{
  "permissions": {
    "project.update": true,
    "project.delete": false,
    "billing.view": true
  }
}
```

프론트엔드는 이 값을 기준으로 버튼 노출, 메뉴 비활성화, 안내 문구를 결정합니다. 역할과 조직 정책의 해석은 서버에 남기고, 화면은 행동 가능 여부만 사용합니다.

## 숨김과 비활성화를 구분한다

권한이 없는 기능을 무조건 숨기면 화면은 깔끔합니다. 하지만 사용자는 기능이 존재하는지도 모를 수 있습니다. 반대로 모든 버튼을 보여주고 비활성화하면 학습에는 좋지만 화면이 무거워집니다.

실무에서는 기능의 성격에 따라 나누는 편이 좋습니다.

- 사용자가 요청해서 얻을 수 있는 권한이면 비활성화하고 이유를 보여준다.
- 플랜 업그레이드와 연결된 기능이면 노출하되 다음 행동을 안내한다.
- 내부 운영자 전용 기능처럼 사용자에게 의미가 없으면 숨긴다.
- 위험한 삭제나 결제 기능은 권한이 있어도 확인 단계를 둔다.

이 기준을 디자인 시스템 문서나 컴포넌트 규칙으로 남겨두면 화면마다 다른 결정을 줄일 수 있습니다.

## 서버 실패를 정상 흐름으로 다룬다

프론트엔드가 권한을 알고 있어도 서버 검증은 반드시 다시 일어납니다. 권한은 세션 중에 바뀔 수 있고, 여러 탭에서 오래 열린 화면은 최신 상태가 아닐 수 있습니다. 그래서 `403 Forbidden`은 예외적인 버그가 아니라 처리해야 할 정상 흐름입니다.

좋은 처리 방식은 사용자의 행동 맥락을 잃지 않는 것입니다. 단순히 "오류가 발생했습니다"라고 말하기보다 "이 작업을 수행할 권한이 없습니다. 권한이 변경되었을 수 있습니다."처럼 원인을 좁혀 줍니다. 목록 화면이라면 데이터를 새로고침하고, 편집 화면이라면 읽기 전용 상태로 전환하는 식의 복구 경로도 필요합니다.

## 권한 체크를 컴포넌트에 흩뿌리지 않는다

여러 화면에서 `if (user.role === "admin")` 같은 조건이 반복되면 권한 정책 변경이 어렵습니다. 최소한 권한 확인 함수나 작은 컴포넌트로 감싸는 편이 좋습니다.

```tsx
function can(permission: PermissionKey) {
  return currentUser.permissions[permission] === true;
}

{can("project.delete") && (
  <DeleteProjectButton projectId={project.id} />
)}
```

더 중요한 점은 권한 이름을 타입으로 관리하는 것입니다. 문자열이 흩어지면 오타가 런타임 버그로 남습니다. 권한 키 목록을 API 스키마나 공유 타입에서 생성하면 프론트엔드와 백엔드의 어긋남을 줄일 수 있습니다.

## 체크리스트

- 프론트엔드 권한 처리를 보안 장치로 착각하지 않는다.
- 역할 이름보다 행동 가능 여부를 UI에 전달한다.
- 숨김, 비활성화, 업그레이드 안내 기준을 나눈다.
- `403` 응답을 사용자가 이해할 수 있는 흐름으로 처리한다.
- 권한 키를 중앙에서 관리하고 타입으로 보호한다.

권한을 아는 UI의 목표는 막는 것이 아니라 헷갈리지 않게 하는 것입니다. 최종 방어선은 서버에 두고, 프론트엔드는 사용자가 가능한 행동만 자연스럽게 발견하도록 돕는 쪽이 더 오래 갑니다.
