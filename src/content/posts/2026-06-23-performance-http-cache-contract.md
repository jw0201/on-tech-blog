HTTP 캐시는 성능 최적화 중에서도 비용 대비 효과가 큽니다. 하지만 백엔드가 임의로 `Cache-Control`을 붙이고 프론트엔드가 우연히 빨라지는 방식은 오래가지 않습니다. 캐시는 "이 데이터가 얼마나 오래 틀려도 되는가"에 대한 제품 계약입니다.

## 데이터 성격부터 분류한다

모든 응답에 같은 캐시 정책을 적용하면 문제가 생깁니다. 자주 바뀌지 않는 공개 데이터와 사용자별 권한 데이터는 완전히 다르게 다뤄야 합니다.

간단한 분류는 다음과 같습니다.

- 정적 자산: 해시가 붙은 JS, CSS, 이미지
- 공개 참조 데이터: 카테고리, 지역 목록, 설정 메타데이터
- 사용자별 데이터: 프로필, 알림, 권한
- 실시간성 데이터: 재고, 가격, 결제 상태
- 민감 데이터: 개인정보, 토큰, 계정 상태

정적 자산은 길게 캐시해도 되지만, 민감 데이터는 공유 캐시에 저장되면 안 됩니다. 캐시 정책은 성능보다 데이터 성격을 먼저 따라야 합니다.

## 화면이 허용하는 staleness를 정한다

사용자는 모든 데이터가 실시간이라고 기대하지 않습니다. 블로그 글 목록, 설정 메타데이터, 도움말 문서는 몇 분 늦어도 괜찮습니다. 반면 결제 상태나 보안 설정은 늦으면 안 됩니다.

프론트엔드와 백엔드는 화면 단위로 허용 가능한 오래된 정도를 정해야 합니다.

```text
blog post list:
  max-age=300, stale-while-revalidate=60

account security settings:
  no-store

product detail:
  max-age=60, stale-while-revalidate=300
```

이 값은 기술자가 감으로 정하기보다 제품 요구사항과 운영 비용을 함께 보고 정하는 것이 좋습니다.

## ETag로 재검증 비용을 줄인다

항상 새 데이터를 내려주지 않아도 됩니다. `ETag`를 사용하면 클라이언트는 가지고 있는 버전을 서버에 확인하고, 변경이 없으면 `304 Not Modified`를 받을 수 있습니다.

```http
ETag: "post-list-v42"
Cache-Control: public, max-age=60
```

클라이언트는 다음 요청에 `If-None-Match`를 보냅니다.

```http
If-None-Match: "post-list-v42"
```

ETag는 응답 본문이 실제로 바뀔 때만 바뀌어야 합니다. 매 요청마다 현재 시각이 포함되면 ETag의 장점이 사라집니다.

## 사용자별 응답은 공유 캐시를 조심한다

`public`과 `private`의 차이를 정확히 이해해야 합니다. `public`은 CDN 같은 공유 캐시에 저장될 수 있다는 뜻이고, `private`은 브라우저 같은 개인 캐시에만 저장하라는 뜻입니다.

사용자별 응답에는 보통 다음이 안전합니다.

```http
Cache-Control: private, max-age=60
Vary: Authorization, Cookie
```

민감한 응답은 더 강하게 막습니다.

```http
Cache-Control: no-store
```

인증된 API에 무심코 `public`을 붙이면 다른 사용자 데이터가 노출될 수 있습니다. 성능 최적화가 보안 사고가 되는 지점입니다.

## 캐시 무효화보다 URL 버전을 선호한다

정적 자산은 캐시를 지우는 방식보다 파일 이름에 해시를 붙이는 방식이 안전합니다.

```text
app.4f3a9c.js
styles.91ab2.css
```

내용이 바뀌면 URL이 바뀌고, 바뀌지 않으면 오래 캐시할 수 있습니다. API 응답도 비슷하게 버전이 명확한 리소스는 URL이나 쿼리 키에 버전을 반영하면 무효화 부담이 줄어듭니다.

## 체크리스트

- 응답을 데이터 성격별로 분류했다.
- 화면 단위로 허용 가능한 staleness를 정했다.
- 변경이 적은 응답에는 ETag 재검증을 고려한다.
- 사용자별 응답은 `private`, `Vary`, `no-store`를 명확히 쓴다.
- 정적 자산은 해시 URL과 긴 캐시를 함께 사용한다.

HTTP 캐시는 헤더 몇 줄이 아니라 사용자 경험, 데이터 신뢰도, 보안 경계가 만나는 계약입니다. 그 계약을 명확히 할수록 성능 개선은 더 안전해집니다.
