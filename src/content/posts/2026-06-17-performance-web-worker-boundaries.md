웹 워커는 메인 스레드의 부담을 줄이는 좋은 도구입니다. 큰 JSON 파싱, 이미지 처리, 검색 인덱싱, 압축, 복잡한 계산을 워커로 옮기면 UI 멈춤을 줄일 수 있습니다. 하지만 무거운 함수를 워커 파일로 옮기는 것만으로 끝나지는 않습니다. 워커는 스레드가 하나 더 생기는 것이고, 그 사이에는 명확한 경계가 필요합니다.

## 먼저 메인 스레드 문제인지 확인한다

워커를 도입하기 전에 병목이 정말 메인 스레드인지 확인해야 합니다. 네트워크 지연이나 서버 응답 시간이 문제인데 워커를 넣으면 복잡도만 늘어납니다. 브라우저 성능 프로파일러에서 긴 작업이 어디에서 발생하는지 먼저 봅니다.

좋은 후보는 다음과 같습니다.

- 50ms 이상 메인 스레드를 자주 막는 계산
- 입력 중 UI가 멈추는 필터링이나 정렬
- 대량 데이터 파싱과 변환
- 렌더링과 직접 관계없는 백그라운드 처리

반대로 DOM 접근이 필요한 작업은 워커로 옮기기 어렵습니다. 워커는 DOM을 직접 만질 수 없기 때문입니다.

## 메시지 계약을 작게 만든다

워커와 메인 스레드는 메시지로 통신합니다. 이 메시지 계약이 느슨하면 유지보수가 어려워집니다. 요청과 응답 타입을 명확히 정의하고, 작업 이름과 payload를 구분합니다.

```ts
type WorkerRequest =
  | { id: string; type: "BUILD_INDEX"; documents: Document[] }
  | { id: string; type: "SEARCH"; query: string };

type WorkerResponse =
  | { id: string; type: "SUCCESS"; result: unknown }
  | { id: string; type: "ERROR"; message: string };
```

`id`는 여러 요청이 동시에 들어올 때 응답을 매칭하는 데 필요합니다. 단일 작업만 가정하고 만들면 나중에 확장할 때 꼬이기 쉽습니다.

## 전달 비용을 계산한다

워커로 데이터를 보낼 때는 복사 비용이 생길 수 있습니다. 작은 계산을 워커로 옮겼는데 큰 객체를 매번 복사하면 오히려 느려질 수 있습니다. 대용량 바이너리 데이터라면 `Transferable` 객체를 활용하고, 반복 요청에서는 워커 내부에 인덱스나 캐시를 유지하는 방식을 고려합니다.

핵심은 "계산이 무겁다"만 보지 말고 "입출력 데이터가 얼마나 큰가"를 함께 보는 것입니다. 워커 경계는 성능 최적화 지점이면서 비용이 발생하는 지점입니다.

## 취소와 최신성 정책을 둔다

검색 입력처럼 사용자가 빠르게 값을 바꾸는 기능에서는 오래된 워커 응답이 뒤늦게 도착할 수 있습니다. 이때 이전 결과가 최신 화면을 덮어쓰면 버그가 됩니다.

간단한 방법은 요청 ID를 기준으로 최신 요청만 반영하는 것입니다. 더 적극적으로는 `AbortController`와 유사한 취소 메시지를 워커에 보내 작업을 중단합니다. 작업이 길다면 워커 내부 루프도 중간중간 취소 플래그를 확인해야 합니다.

## 에러를 직렬화한다

워커 내부에서 발생한 에러는 메인 스레드로 전달될 때 정보가 줄어들 수 있습니다. 에러 객체를 그대로 믿기보다 메시지, 코드, 원인 타입을 명시적으로 직렬화합니다. 운영 로그에는 워커 작업 타입과 입력 크기 같은 맥락도 함께 남기는 편이 좋습니다.

```ts
postMessage({
  id,
  type: "ERROR",
  code: "INDEX_BUILD_FAILED",
  message: error instanceof Error ? error.message : "Unknown error"
});
```

## 체크리스트

- 성능 프로파일러로 메인 스레드 긴 작업을 먼저 확인한다.
- 워커 요청과 응답 타입을 명확히 정의한다.
- 데이터 복사 비용과 `Transferable` 사용 가능성을 검토한다.
- 오래된 응답을 무시하거나 작업 취소 정책을 둔다.
- 워커 에러를 직렬화하고 로그 맥락을 남긴다.

웹 워커는 성능 문제를 숨기는 마법 상자가 아닙니다. 경계가 분명할 때만 UI 반응성을 지키는 좋은 구조가 됩니다. 무거운 계산을 옮기기 전에 메시지 계약부터 설계하는 이유가 여기에 있습니다.
