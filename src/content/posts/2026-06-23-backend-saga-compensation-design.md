여러 서비스에 걸친 작업은 하나의 데이터베이스 트랜잭션처럼 되돌릴 수 없습니다. 주문 생성, 결제 승인, 재고 차감, 배송 요청이 각각 다른 시스템에서 일어난다면 중간 실패는 반드시 발생합니다. 사가 패턴은 이 문제를 각 단계와 보상 단계를 명시해서 다룹니다.

중요한 점은 보상 트랜잭션이 진짜 롤백이 아니라는 사실입니다. 이미 외부 시스템에 전달된 효과를 반대 방향의 작업으로 보정하는 것입니다.

## 보상 가능한 작업인지 먼저 묻는다

모든 작업에 보상이 있는 것은 아닙니다. 이메일 발송, 외부 정산, 물류 출고처럼 이미 현실 세계에 영향을 준 작업은 완전히 되돌릴 수 없습니다. 이런 단계는 사가의 뒤쪽으로 미루거나, 실행 전에 승인 대기 상태를 둬야 합니다.

실무에서는 각 단계를 다음처럼 분류하면 설계가 선명해집니다.

- 즉시 보상 가능: 포인트 적립 취소, 예약 해제
- 조건부 보상 가능: 결제 취소, 쿠폰 복구
- 보상 불가: 이메일 발송, 송장 출력, 외부 신고
- 수동 보상 필요: 이미 출고된 배송, 회계 전표 수정

보상 불가 단계가 앞에 있으면 사가는 실패할 때마다 운영팀의 일을 만듭니다.

## 단계마다 상태를 남긴다

사가 실행 상태는 로그만으로 추적하면 안 됩니다. 각 단계의 시작, 성공, 실패, 보상 완료를 저장해야 재시작과 수동 복구가 가능합니다.

```text
order_saga
- saga_id
- order_id
- current_step
- status
- last_error
- retry_count
- created_at
- updated_at

order_saga_steps
- saga_id
- step_name
- status
- idempotency_key
- completed_at
```

이 상태 테이블은 운영 도구의 근거가 됩니다. 어떤 주문이 결제는 되었지만 재고 차감에 실패했는지, 어떤 보상 단계가 반복 실패 중인지 바로 볼 수 있어야 합니다.

## 멱등성을 기본값으로 둔다

사가에서 재시도는 예외가 아니라 정상 흐름입니다. 네트워크 타임아웃이 발생했을 때 호출이 실제로 성공했는지 실패했는지 모를 수 있습니다. 따라서 각 단계와 보상 단계는 같은 키로 여러 번 호출되어도 결과가 같아야 합니다.

멱등성 키는 보통 `saga_id + step_name`으로 만들 수 있습니다. 외부 API가 멱등성 키를 지원한다면 반드시 전달하고, 지원하지 않는다면 내부에서 호출 기록을 보관해야 합니다.

```text
reserve-stock: saga_123:reserve_stock
cancel-payment: saga_123:cancel_payment
```

보상 작업도 멱등해야 합니다. 결제 취소 요청이 두 번 나가도 한 번만 취소되어야 하고, 이미 취소된 결제에는 성공으로 응답하는 편이 운영상 안전합니다.

## 보상 순서는 역순이 기본이다

대부분의 경우 보상은 성공한 단계의 역순으로 실행합니다. 주문 생성, 결제 승인, 재고 차감 순서로 진행했다면 재고 복구, 결제 취소, 주문 취소 순서가 자연스럽습니다.

하지만 항상 기계적인 역순이 정답은 아닙니다. 결제 취소가 재고 복구보다 더 긴급할 수 있고, 외부 시스템의 제약 때문에 특정 보상을 먼저 해야 할 수도 있습니다. 그래서 보상 순서는 코드에 흩뿌리지 말고 사가 정의에 명시하는 것이 좋습니다.

## 사람이 개입할 지점을 만든다

사가가 반복 실패하면 무한 재시도보다 격리 상태로 보내야 합니다. 예를 들어 결제 취소 API가 계속 실패한다면 운영자가 확인할 수 있는 큐로 이동하고, 고객에게 노출되는 상태는 "처리 확인 중"처럼 별도로 관리해야 합니다.

필요한 운영 정보는 다음과 같습니다.

- 실패한 단계와 마지막 에러
- 이미 성공한 단계 목록
- 실행된 보상 단계 목록
- 다시 시도 가능한 버튼
- 수동 완료 처리와 감사 로그

운영 UI가 없으면 사가 장애는 데이터베이스 쿼리와 슬랙 메시지로 처리됩니다. 그 상태는 오래 버티기 어렵습니다.

## 체크리스트

- 각 단계가 보상 가능한지 분류했다.
- 사가와 단계별 실행 상태를 저장한다.
- 모든 단계와 보상 단계에 멱등성 키가 있다.
- 보상 순서를 명시적으로 정의한다.
- 반복 실패 시 수동 처리 경로와 감사 로그가 있다.

사가 패턴의 핵심은 완벽한 롤백이 아닙니다. 실패를 예상 가능한 상태로 만들고, 자동 복구와 수동 복구가 같은 기록을 보게 만드는 것입니다.
